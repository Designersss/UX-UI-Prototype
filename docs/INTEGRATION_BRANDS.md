# Integration logo sources and usage

All currently displayed third-party integrations use real provider SVG assets from the archived prototype (no imitation letters or emoji). Assets are bundled locally so the mock UI works offline.

| ID | Provider | Bundled asset | Notes |
|---|---|---|---|
| `telegram` | Telegram | `telegram.svg` | Brand color + icon |
| `max` | MAX | `max.svg` | Brandbook colors; confirm final mark against official kit |
| `vk` | VK | `vk.svg` | Brand icon |
| `whatsapp` | WhatsApp | `whatsapp.svg` | Brand icon; follow official Meta guidelines |
| `viber` | Viber | `viber.svg` | Brand color + icon |
| `bitrix` / `bitrix24` | Bitrix24 | `bitrix24.svg` | Existing icon artwork; verify final use against brand's approved assets before production |
| `googlecalendar` | Google Calendar | `googlecalendar.svg` | Existing icon artwork; verify against latest official icon |

**Other provider classes in Product Specification v1.6:** HeadHunter (hh.ru), generic email, generic web chat and CRM/calendar adapters. These are not populated as mock integration records in Overview yet. We will add provider-specific *verified* logos together with each actual connector, never invent brand marks. Generic `email` and own-site `webchat` have no third-party brand, so they intentionally use a neutral product pictogram. Do not imply target API availability by presence of a logo.

References: MAX https://go.max.ru/brandbook; Bitrix24 https://www.bitrix24.com/about/brand-guidelines.php; WhatsApp https://www.meta.com/brand/resources/whatsapp/whatsapp-brand/.
